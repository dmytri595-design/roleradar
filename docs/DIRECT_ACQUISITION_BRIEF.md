# RoleRadar — Direct Acquisition Brief

## Offer

**RoleRadar — Explainable Identity Access Reviews** is a working, browser-local B2B security workflow MVP offered for a one-time asset acquisition.

- Asking price: **US$4,500**, open to a serious cash offer.
- Demo: https://roleradar-demo.vercel.app
- Source repository: https://github.com/dmytri595-design/roleradar
- Project stage: pre-launch / pre-revenue. No customers, MRR, or production deployments are claimed.

## What the buyer gets

- Self-contained HTML/CSS/JavaScript application and repository history.
- Synthetic sample identity dataset.
- CSV import and normalization, configurable deterministic risk rules, identity inventory, evidence detail, and remediation states.
- Owner / due-date tracking, bulk remediation, policy editor, review history, CSV export, JSON evidence pack, and HTML audit report.
- Existing README, listing, valuation memo, acquisition brief, and automated validation / browser smoke-test assets.
- Live demo and an agreed handover of the accounts and assets that are actually transferable.

## Demo scope — explicitly disclosed

The public demo runs locally in the browser. It has no production authentication, multi-tenant backend, cloud database, or native Okta / Microsoft Entra / Google Workspace connectors. Its demo identities are synthetic. It does not certify compliance or replace a production identity-governance platform.

## Important licensing and rights condition

The public repository currently carries the **MIT License**. Existing copies distributed under that license retain the permissions granted by it; the sale must not be presented as an exclusive transfer of every copy of the published source code or as an ability to revoke existing MIT grants.

A transaction can instead cover the seller's copyright interest where legally transferable, the project name/branding and other owned materials, repository control, demo/deployment assets, documentation, and a written assignment or license for any rights that are actually available to transfer. Any third-party or open-source components remain subject to their own terms. Exact scope must be listed in the purchase agreement.

## Suggested transaction approach

1. Buyer reviews the public demo and repository.
2. Parties agree in writing on price, included assets, license treatment, and handover.
3. Payment is secured and release conditions are agreed before any account, ownership, or private asset transfer.
4. Transfer occurs against the signed agreement and payment confirmation.

The project is offered as an asset package, not as a profitable operating company. An inquiry or demo is not an offer and does not commit either party to a sale.
